# Contrib Files

| File | Purpose |
|------|---------|
| `PKGBUILD` | Arch Linux package (`pwsw-git`, built from the latest commit) |
| `pwsw.service` | systemd user unit for the daemon |
| `pwsw.desktop` | Desktop entry that opens the TUI in a terminal |
| `icons/` | Application icon (SVG source plus PNG sizes, see `icons/README.md`) |
| `noctalia/` | Noctalia v5 bar plugin following `pwsw status --watch --json` (see `noctalia/README.md`; untested by CI) |
| `screenshots/` | TUI screenshots used by the top-level README |

## Arch Linux package

```bash
cd contrib
makepkg -si
```

The Rust toolchain comes from `rustup`, which honours the repository's
`rust-toolchain.toml` (the pinned Rust version). `check()` runs the test suite with
HOME/XDG pointed into a throwaway directory under `$srcdir`, so it never sees your
real pwsw config, daemon or audio session (skip it with `makepkg --nocheck`).

Installed files:

| Path | Contents |
|------|----------|
| `/usr/bin/pwsw` | the binary |
| `/usr/lib/systemd/user/pwsw.service` | the user unit (see below) |
| `/usr/share/man/man1/pwsw.1`, `/usr/share/man/man5/pwsw.5` | man pages (generated by `build.rs`) |
| `/usr/share/bash-completion/completions/pwsw` | bash completions |
| `/usr/share/zsh/site-functions/_pwsw` | zsh completions |
| `/usr/share/fish/vendor_completions.d/pwsw.fish` | fish completions |
| `/usr/share/applications/pwsw.desktop` | desktop entry |
| `/usr/share/icons/hicolor/{16x16..512x512,scalable}/apps/pwsw.*` | icons |
| `/usr/share/licenses/pwsw-git/LICENSE` | license |

**Debug package:** Cargo's release profile strips the binary (`strip = true`, for
`cargo install` users). The PKGBUILD overrides that for the package build
(`CARGO_PROFILE_RELEASE_STRIP=false`) so makepkg does the stripping itself: with
`debug` in `OPTIONS` (makepkg.conf) or `options=(debug)`, the symbols end up in a
separate `pwsw-git-debug` package. makepkg's `DEBUG_RUSTFLAGS` (`-C debuginfo=2` by
default) decides how much debug info that is.

**Notifications** need a notification server (mako, dunst, swaync, the one your
desktop ships, ...). The package does not depend on one: without it pwsw works the
same, only without notifications.

After installing, create the config and add your sinks before enabling the service
(the daemon refuses to start without configured sinks and never creates the config):

```bash
pwsw init      # commented template at ~/.config/pwsw/config.toml
pwsw tui       # or configure sinks and rules interactively
```

## Systemd Service

Start the daemon automatically on login (after `pwsw init` / `pwsw tui` above):

```bash
systemctl --user enable --now pwsw.service
```

Check status:

```bash
systemctl --user status pwsw.service
```

View logs (also written to `~/.local/share/pwsw/daemon.log`, which the TUI shows):

```bash
journalctl --user -u pwsw.service -f
```

### What the unit does

- **Session lifecycle:** `WantedBy=`/`PartOf=`/`After=graphical-session.target`, so it
  starts once your graphical session (and `WAYLAND_DISPLAY`) is up and stops with it.
  Your compositor must start `graphical-session.target` (most do via a systemd/uwsm
  integration); otherwise start it manually.
- **PipeWire:** `Wants=` + `After=pipewire.service`. pwsw holds no PipeWire connection
  (it runs `pw-dump`/`pw-cli`/`pw-metadata` per action), so it is not bound to
  PipeWire's lifetime and keeps running across PipeWire restarts.
- **Readiness and status:** `Type=notify`: the unit is active once the daemon is set
  up, and `systemctl --user status pwsw` shows the current sink (`Sink: X · Mic: Y` with
  `[[sources]]`, `(paused)` while paused).
- **Restarts:** `Restart=on-failure` every 5 s, at most 5 starts per 60 s.
- **Sandbox:** `ProtectSystem=strict` (everything read-only, including your home)
  except `~/.local/share/pwsw` (log) and `$XDG_RUNTIME_DIR` (socket and lock file); the
  config is only read; private `/tmp`; `NoNewPrivileges`, `MemoryDenyWriteExecute`, `LockPersonality`,
  `RestrictRealtime`, `RestrictSUIDSGID`, `SystemCallArchitectures=native`,
  `UMask=0077`. `ExecStartPre=+mkdir -p …` creates the log directory outside
  the sandbox so a first start works.

If you set `XDG_CONFIG_HOME`/`XDG_DATA_HOME` to non-default locations, adjust
`ReadWritePaths=` and the `ExecStartPre=` line (the daemon only needs to *write* the
log directory; the config is read).

### Manual Installation (cargo users)

If you installed via `cargo install` instead of a package (completions:
`pwsw completions <shell>`, see the top-level README; man pages are only installed
by the package):

```bash
mkdir -p ~/.config/systemd/user
cp contrib/pwsw.service ~/.config/systemd/user/

# Point ExecStart at the cargo binary (systemd expands %h to your home; `~` is not expanded)
sed -i 's|^ExecStart=/usr/bin/pwsw|ExecStart=%h/.cargo/bin/pwsw|' ~/.config/systemd/user/pwsw.service

systemctl --user daemon-reload
systemctl --user enable --now pwsw.service
```

Check the edited unit with `systemd-analyze --user verify ~/.config/systemd/user/pwsw.service`.

## Without systemd

`pwsw daemon` starts a detached background daemon (own process group, survives the
terminal closing) and waits until it answers on its socket. If it fails to start,
the error and the last lines of `~/.local/share/pwsw/daemon.log` are printed.
